# KlipperScreen (farm-wide touchscreen)

A standalone wireless KlipperScreen that connects to every Klipper printer in the farm over the network (Moonraker). It is not attached to any printer.

## Hardware / host

| | |
|---|---|
| Device | Microsoft Surface Pro (1st gen, 2013, "Surface with Windows 8 Pro") |
| OS | Debian 12 (bookworm), kernel 6.1 amd64 |
| Network | Wi-Fi only, built-in Marvell adapter (`wlx6045bdd6ff2a`). IP `192.168.1.218` |
| SSH | `pi@192.168.1.218` (key auth). The user is named `pi` even though this isn't a Raspberry Pi |
| KlipperScreen | v0.3.9-71-gaae9e84 (April 2024), installed in `~/KlipperScreen` |
| Service | `KlipperScreen.service`, runs as `pi` |

## Files

| Repo file | On device |
|---|---|
| `KlipperScreen.conf` | `/home/pi/KlipperScreen/KlipperScreen.conf` |

⚠️ The **active** config is `~/KlipperScreen/KlipperScreen.conf` (inside the install dir). `~/KlipperScreen.conf` in the home dir is a stale two-printer copy that isn't loaded. Confirm with the `Config path location:` line in the log.

The `#~#` block at the bottom of the config is auto-generated by KlipperScreen (UI settings saved from the screen). Like Klipper's SAVE_CONFIG block, don't edit it by hand, and keep it when copying the config back.

## ⚠️ Never set `moonraker_api_key: False`

This KlipperScreen version treats `False` as a literal string and sends `X-Api-Key: False`. Starting with **Moonraker v0.11**, a request carrying an invalid API key is rejected with **401 Unauthorized**, even from a trusted client IP. When the printers auto-updated Moonraker on 2026-11-25, every printer on the screen stopped connecting.

Fix: leave the line commented out, as it is now. The screen authenticates as a trusted client, so each printer's `moonraker.conf` `[authorization] trusted_clients` must include `192.168.1.0/24` (or the screen's IP).

## Deploy / troubleshoot

```bash
# push config
scp klipperscreen/KlipperScreen.conf pi@192.168.1.218:KlipperScreen/KlipperScreen.conf
# restart (sudo needs a password, so use an interactive session, or reboot the Surface)
ssh -t pi@192.168.1.218 sudo systemctl restart KlipperScreen

# pull config back after changing settings on the screen
scp pi@192.168.1.218:KlipperScreen/KlipperScreen.conf klipperscreen/

# log
ssh pi@192.168.1.218 tail -50 /tmp/KlipperScreen.log

# test a printer from the screen's point of view (expect 200)
ssh pi@192.168.1.218 curl -s -o /dev/null -w '%{http_code}\n' http://192.168.1.47:7125/server/info
```

Known issue: `[menu __main] name: {{ gettext('Main Menu') }` is missing its closing `}`. It has been like that since before this was added to the repo and KlipperScreen loads anyway. Fix it if the main menu title looks wrong.
